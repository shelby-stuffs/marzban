# Hysteria2 / Xray — этап 2: проверки до сохранения

Накопительный пакет на базе hysteria-refactor-stage1.zip. Сохраняет общий
клиентский профиль, предыдущие исправления и исходники терминальной темы.
Frontend в этом этапе не менялся и не пересобран.

## Реализовано
Новый app/utils/hysteria2_validation.py содержит чистые функции без записи,
генерации ключей или неявной миграции конфигурации.

1. Сохранение core/config, XHTTP и WireGuard:
   - Проверка native Hysteria2 до построения конфигурации и после добавления
     пользователей БД, до штатного xray run -test, записи и рестарта.
   - Проверяются method/network=hysteria, TLS, settings.version=2,
     hysteriaSettings.version=2, один integer UDP-порт 1..65535, auth и форма
     массивов clients/users. Пустые clients до добавления пользователей разрешены.
   - Дубли auth и одновременные непустые users/clients отклоняются.
   - Legacy obfs в hysteriaSettings не мигрируется молча: администратор получает
     ошибку с указанием необходимости явного переноса в finalmask.udp.
   - Для подписок этого проекта разрешён plain Salamander. Несколько UDP-масок,
     другие маски и Gecko/расширенные параметры отклоняются, а не упрощаются с
     потерей совместимости. Это ограничение ПАНЕЛИ, не утверждение о возможностях Xray.
   - Неизвестные прочие поля конфигурации не удаляются; штатная проверка бинарником
     остаётся обязательной. Сертификаты, listen, quicParams и прочие параметры
     по-прежнему проверяются ядром, а не этим ограниченным Python-валидатором.

2. PUT /api/hosts:
   - Весь присланный пакет проверяется до первого crud.update_hosts.
   - Проверяются эффективные Hysteria-параметры после наследования от inbound.
   - Некорректный активный хост отклоняется с HTTP 400 до записи; отключённый
     хост можно сохранить и исправить до включения.
   - Статические адреса проверяются общей моделью. Для динамических шаблонов
     проверяется лишь синтаксис скобок: подстановки доступны только при генерации.

3. UserCreate/UserModify:
   - Непустой строковый auth Hysteria проверяется только в моделях записи.
   - Модели чтения не получили это новое ограничение, БД не переписывается.
   - Отсутствующий auth по-прежнему генерируется существующей моделью настроек.
   - Проверка не вводит уникальность auth во всей БД и не тестирует gRPC.

4. Общее наследование хоста:
   - Сохранение и генерация подписок используют один resolve_hysteria2_host.
   - Явный allowinsecure=False больше не заменяется унаследованным True.
   - Существующая семантика пустого obfs/password сохранена: пусто = наследовать.
     Надпись none в старом UI при value="" пока вводит в заблуждение; исправление
     формы и явное разделение inherit/none запланировано следующим этапом.

## Проверки
Новый tests/test_hysteria2_save_validation.py: 21 успешный тест.
Предыдущие: 17 профиль + 19 Xray JSON + 14 inbound. Всего 71 успешный тест.
Компиляция app/cli/xray_api успешна.

Из корня проекта:

```bash
python -m unittest discover -s tests -p test_hysteria2_save_validation.py -v
python -m unittest discover -s tests -p test_hysteria2_profile.py -v
python -m unittest discover -s tests -p test_hysteria2_xray_json.py -v
python -m unittest discover -s tests -p test_hysteria2_inbound.py -v
python -m compileall -q app cli xray_api
```

Тесты маршрутов исполняют их настоящие тела через AST, но HTTP-исключения,
запись, БД, XrayConfig, binary-test и рестарты заменены тестовыми объектами.
Методы пользовательской валидации проверены реальным Pydantic на минимальной
модели. Это НЕ полноценные HTTP/DB/интеграционные тесты приложения.
Штатная проверка настоящим бинарником Xray сохранена в коде, но здесь не запускалась.

## Важные границы и совместимость
- Старые несовместимые данные не мигрируются и не исправляются автоматически.
  Ошибка при экспорте старой подписки всё ещё возможна до проверки таких данных.
- Дополнительный Python-guard не подключён к старту приложения: уже сохранённая
  конфигурация не изменяется. На сохранении через три перечисленных маршрута
  проверяется ВСЯ конфигурация: несовместимый старый Hysteria inbound может
  заблокировать сохранение даже изменений XHTTP/WireGuard до исправления.
- Межтеговая транзакционность CRUD не переработана. Предварительная ошибка
  валидации больше не вызывает частичную запись, но сбой БД после начала записи
  всё ещё зависит от прежней реализации с отдельными commit.
- При изменении core не выполняется аудит всех существующих хостов/пользователей.
  Полный read-only аудит и сценарий миграции нужны до production-развёртывания.
- Устойчивость при сбое диска/рестарта, TLS handshake, добавление/отзыв через gRPC,
  лимиты и статистика на настоящем Xray пока не проверены.
