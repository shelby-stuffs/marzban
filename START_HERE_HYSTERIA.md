# Итоговый пакет Hysteria2 / Xray — передача на проверку

Это единый накопительный архив для тестирования и дальнейшей установки.
Не нужно накатывать архивы этапов поверх него. Все прошлые исправления Hysteria,
общий профиль подписок и исходники терминального оформления включены.

**Статус: кандидат для тестового запуска, НЕ подтверждённая production-сборка.**
Нет автоматической миграции, автоматического деплоя или обещания проверенного
подключения на настоящем Xray. БД и рабочий сервер в этой сессии не трогались.

## Что закончено в исходниках
- Единый профиль ссылки / Xray JSON / sing-box / Clash Meta.
- TLS, ALPN, IPv6, кодирование auth, Salamander finalmask.
- Проверки при записи пользователя, хостов и core-конфига; generic Mux и
  лишний Freedom dialer не возвращены.
- Явный allowinsecure=False не теряется при наследовании.
- В карточке пользователя отображается отдельный редактируемый Hysteria 2 auth:
  новый пользователь получает случайный 32-символьный hex-пароль, рядом есть
  генератор. Смена auth отзывает старые Hysteria 2 конфигурации этого пользователя.
- В существующей форме Hosts: Inherit / No obfs / Salamander.
  Пустое значение = наследовать; строка none = не экспортировать obfs.
  Это параметры ПОДПИСКИ, не изменение сервера: они должны совпадать с сервером,
  указанным в адресе хоста. Пустой пароль наследуется; при No obfs он игнорируется.
- Поля obfs убраны из карточки пользователя, чтобы не смешивать общий серверный
  Salamander-пароль с индивидуальным auth. Старые значения в БД не удаляются.
  Отдельная новая страница управления сервером Hysteria не добавлялась.
- tools/audit_hysteria2.py — read-only проверка локальных JSON-экспортов.
  Ничего не меняет, не подключается к БД/сети и не печатает auth/пароли.

## 1. Подготовка и резервная копия
Распаковать в НОВЫЙ каталог, не поверх работающей установки.
Сохранить текущие исходники/образ, .env, Xray JSON, сертификаты и резервную копию
БД штатным способом для SQLite/PostgreSQL. Не копировать активно меняющийся
SQLite-файл как единственную резервную копию. Проверить восстановление.

Лучший первый запуск — отдельная машина/VM со своими данными и свободными портами.
Существующий docker-compose.yml использует host networking и /var/lib/marzban:
**без адаптации это не изолированная тестовая установка**, даже из другого каталога.

## 2. Локальные тесты
Python 3.10+; для текущего проекта рекомендуются версии из его окружения/Dockerfile.
В окружении должны быть зависимости проекта, включая Pydantic 2.

```bash
for suite in profile xray_json inbound save_validation audit; do
  python -m unittest discover -s tests -p "test_hysteria2_${suite}.py" -v || exit 1
done
python -m compileall -q app cli xray_api tools/audit_hysteria2.py
```

Здесь успешно выполнены 82 теста (17+19+14+21+7+4 UI-контракта) и compileall.
Тесты маршрутов используют реальные тела функций через AST и тестовые замены
БД/ядра. Это не полные HTTP/DB/gRPC-тесты. 62 TS/TSX-файла разобраны синтаксически;
полный tsc и production-сборка фронтенда здесь НЕ выполнены.

## 3. Аудит старых данных
Сохранить локально строгий JSON из GET /api/core/config и GET /api/hosts.
Для пользователей нужен полный экспорт GET /api/users: все страницы, объединённые
в массив, либо объект {"users": [...], "total": N}. Не отправлять эти файлы в чат:
они содержат секреты. Файлы с комментариями не являются строгим JSON.
Используйте действующие права администратора и обычный способ экспорта API.

```bash
python tools/audit_hysteria2.py \
  --core /path/to/core.json \
  --hosts /path/to/hosts.json \
  --users /path/to/users.json
```

Коды завершения: 0 — нет выявленных ошибок (предупреждения возможны),
1 — найдены ошибки, 2 — входные файлы не удалось прочитать/разобрать.
Отчёт обязан быть просмотрен: coverage=false, partial_users_export и предупреждения
означают неполную проверку, даже при коде 0. Динамические адреса проверяются только
по синтаксису; сертификаты и сетевое подключение этот аудит не проверяет.

При legacy_user_obfs сравнить старые значения с сервером и хостом. Не переносить
пароли автоматически: у разных хостов могут быть разные серверы. При несовпадении
выбрать правильные host/inbound настройки вручную. Не удалять старые поля до проверки.
Непереносимые цепочки FinalMask, Gecko, legacy transport obfs и смешанные clients/users
исправлять явно; панель не должна молча упрощать рабочий серверный конфиг.

## 4. Собрать фронтенд
Новая тема и подписи формы находятся в исходниках. Включённый каталог build старый!
Сеть для установки npm-зависимостей нужна. Здесь установка остановилась из-за
отсутствующей в офлайн-кэше зависимости Monaco, поэтому готового нового build нет.

```bash
cd app/dashboard
npm install --no-audit --no-fund
VITE_BASE_API=/api/ npm run build -- --outDir build --assetsDir statics
cp build/index.html build/404.html
cd ../..
```

Если установка/сборка завершилась ошибкой — остановиться, не деплоить старый build
как будто он содержит новый интерфейс. Сохранить лог ошибки без секретов.

## 5. Собрать свой Docker-образ
Текущий docker-compose.yml указывает на опубликованный shelbyhell/marzban:latest.
Прос��ая распаковка исходников и docker compose up НЕ включат изменения этого архива.
Dockerfile сам фронтенд не собирает — сначала выполнить предыдущий шаг.

```bash
docker build -t marzban:hysteria-review .
```

В архив добавлен compose.hysteria-local.yml, который выбирает локальный образ
и запрещает его случайную замену скачанным image. Запуск с ним:

```bash
docker compose -f docker-compose.yml -f compose.hysteria-local.yml up -d --no-deps marzban
```

**Эту команду выполнять только после настройки изолированного стенда либо
осознанно при установке на сервер после резервной копии и проверок.** Она использует
.env, сеть и volume mounts основного compose-файла. При старте штатный entrypoint
выполняет alembic upgrade head; новых миграций этой переработкой не добавлено,
но на старой установке могут быть неприменённые миграции самого проекта.

## 6. Проверить перед рабочим использованием
- Фактическую версию Xray, проверку конфигурации бинарником и запуск без ошибок.
  Dockerfile закрепляет v26.7.11; здесь эта версия не запускалась.
- Пользователь подключается каждым используемым клиентом: ссылка, Xray JSON,
  sing-box, Clash Meta. Тестировать только поддерживаемые версии клиентов.
- TLS проверяется; SNI/сертификат верны. Не включать allowInsecure ради обхода ошибки.
- Наследование / No obfs / Salamander дают ожидаемые результаты; параметры сервера
  и хоста совпадают. Проверить IPv6, если используется.
- Создание, изменение, отзыв auth и отключение пользователя реально применяются.
- Лимиты, статистика, перезапуск и удалённые ноды работают.
- Не-Hysteria протоколы не сломались.
- Hosts, Users и остальные страницы открываются на десктопе и телефоне.

При ошибке — не расширять установку. Сначала сохранить несекретный лог и откатить
образ/исходники. Если изменялись данные или применились миграции — использовать
проверенный план восстановления БД, а не произвольный downgrade.

## Известные ограничения
См. HYSTERIA2_REFACTOR_STAGE2.md. Аудит не мигрирует данные. Старые ошибочные профили
могут всё ещё ломать генерацию подписок, пока их не исправить. Новые guards проверяют
всю конфигурацию при сохранении, включая сохранение XHTTP/WireGuard. Часть валидных
в Xray расширенных настроек отклоняется как пока непредставимая в подписках панели.
Межтеговая транзакционность CRUD и откат после сбоя рестарта не переработаны.
